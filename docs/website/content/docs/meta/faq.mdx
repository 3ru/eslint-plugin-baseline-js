If a check behaves unexpectedly, open a
[GitHub issue](https://github.com/3ru/eslint-plugin-baseline-js/issues) with your
configuration and a small code sample.

## Why is an API not reported?

- Check that the rule applies to the file. `recommended` covers JavaScript;
  `recommended-ts` covers `.ts` and `.tsx`.
- The `baseline` preset leaves descriptor checks disabled. Use a recommended
  preset to enable Web API and JS builtin descriptors.
- Instance-member descriptors need TypeScript type information. Configure the
  parser and its project as shown in [Quick Start](/docs).
- The receiver's type must contain the member. Missing type declarations can
  prevent a report.
- A feature needs a mapped rule or descriptor. Check the
  [coverage report](/docs/meta/coverage).
- Some dynamic access and alias patterns are not detected.
- The feature must exceed your configured Baseline policy.

```js title="eslint.config.mjs"
import baselineJs from "eslint-plugin-baseline-js";

export default [
  {
    ...baselineJs.configs.recommended({ available: "widely" }),
    plugins: { "baseline-js": baselineJs },
  },
];
```

## Does `type-aware` fail when types are missing?

No. The plugin skips instance-member and `typedOnly` descriptor checks when it
cannot find parser type information. Other supported checks still run.

The parser itself can report an error if a file is outside its configured
TypeScript project.

## Can I use oxlint?

Yes, through its JS plugin support. This plugin's checks that need TypeScript
parser services do not run there. See [Use with oxlint](/docs/oxlint) for setup
and limits.

## Why does the status differ from today's Baseline data?

The plugin bundles a fixed web-features snapshot. It does not download data or
advance availability dates during linting. A newer release may include updated
data and detectors.

## Does the plugin account for polyfills or Node.js versions?

No. It checks source code against browser Baseline data. It does not inspect
installed polyfills, transpiler output, or runtime feature guards.

Setting ESLint globals does not change that policy. Use a narrow exception when
you have verified support for your targets.

## How do I suppress a report?

- `ignoreFeatures` matches web-features IDs, such as `'iterator-join'`.
- `ignoreNodeTypes` matches the reported node's ESTree type, such as `'WithStatement'`.
- Both options accept exact strings or regex patterns such as `'/^iterator-/'`.
- Regex strings must start and end with `/`. Flags such as `/pattern/i` are not supported.
- The `only` and `ignore` lists inside include options accept exact feature IDs only.

## How do I combine presets or change severity?

Recommended presets configure this plugin's rule and file patterns. Register the
plugin under `'baseline-js'` and add your parser separately.

Use flat config objects with `files` and `ignores` to scope changes. Pass `level`
to change a preset's severity without replacing its detection options:

```js
baselineJs.configs.recommended({ available: "widely", level: "warn" });
```

See [Configuration](/docs/config) for the full options.
