description: Set up JavaScript and TypeScript checks and share a Baseline policy.
---

Choose one threshold for your project: `'widely'`, `'newly'`, or a year.
Use both recommended presets when your project contains JavaScript and TypeScript.

## Install

```bash tab="npm"
npm i -D eslint eslint-plugin-baseline-js typescript @typescript-eslint/parser
```

```bash tab="yarn"
yarn add -D eslint eslint-plugin-baseline-js typescript @typescript-eslint/parser
```

```bash tab="pnpm"
pnpm add -D eslint eslint-plugin-baseline-js typescript @typescript-eslint/parser
```

See [Quick Start](/docs) for supported Node.js and ESLint versions.

## Flat config

Keep the TypeScript files in `tsconfig.json`. The parser needs that project to
provide type information.

```js title="eslint.config.mjs"
import baselineJs, { BASELINE } from "eslint-plugin-baseline-js";
import tsParser from "@typescript-eslint/parser";

const available = BASELINE.WIDELY;

export default [
  {
    ...baselineJs.configs.recommended({ available }),
    plugins: { "baseline-js": baselineJs },
    languageOptions: {
      parserOptions: { ecmaFeatures: { jsx: true } },
    },
  },
  {
    ...baselineJs.configs["recommended-ts"]({ available }),
    plugins: { "baseline-js": baselineJs },
    languageOptions: {
      parser: tsParser,
      parserOptions: {
        project: ["./tsconfig.json"],
        tsconfigRootDir: import.meta.dirname,
      },
    },
  },
];
```

The first block covers `.js`, `.cjs`, `.mjs`, and `.jsx`. The second covers `.ts`
and `.tsx`. Override `files` if your project uses other extensions.

The JavaScript block runs without type information. Add a parser project for
JavaScript if you need supported instance-member checks there too.

## Change the threshold

Update the shared `available` value:

- Use `BASELINE.NEWLY` to allow newly and widely available features.
- Use a year such as `2024` to allow features that became Baseline by that year.

## CSS and HTML

Use separate plugins for CSS and HTML:

- [ESLint CSS](https://github.com/eslint/css) provides `css/use-baseline`.
- [HTML ESLint](https://html-eslint.org/docs/getting-started) provides `use-baseline`
  for HTML.

Follow each plugin's setup instructions and version requirements. Scope their
configuration with `files` so JavaScript parser options do not apply to CSS or HTML.

Pass the same `available` value to each Baseline rule. Each plugin has its own
data version and detection coverage, so matching thresholds can still produce
different results.

## Environment globals

Set `languageOptions.globals` in the JavaScript or TypeScript block that needs
those names. This can prevent `no-undef` reports when that rule is enabled.

Global names do not select compatibility targets. The Baseline rule still uses
browser data, including when you configure Node.js globals.

## Exceptions

Use `ignoreFeatures` for specific features and `ignoreNodeTypes` for report node
types. Both accept exact strings or regex patterns written as `'/.../'`.

Document why each exception is safe for your project. The plugin does not verify
polyfills, fallbacks, or runtime feature checks.

Review the [coverage report](/docs/meta/coverage) when you update the plugin.
