title: Quick Start
description: Check JavaScript features against your chosen Baseline target.
---

`eslint-plugin-baseline-js` reports supported JavaScript syntax, built-ins, and Web APIs that exceed your chosen Baseline target.
Choose `widely`, `newly`, or a year. The plugin uses the feature data bundled with each release.

## Install

The plugin supports ESLint `>=9.29.0 <11` and requires Node.js `^20.19.0 || >=22.12.0`.
Your ESLint version can have stricter [Node.js requirements](https://eslint.org/docs/latest/use/getting-started#prerequisites).

```bash tab="pnpm"
pnpm add -D eslint eslint-plugin-baseline-js
```

```bash tab="npm"
npm install -D eslint eslint-plugin-baseline-js
```

```bash tab="yarn"
yarn add -D eslint eslint-plugin-baseline-js
```

```bash tab="bun"
bun add -D eslint eslint-plugin-baseline-js
```

## Configure JavaScript

Create `eslint.config.mjs` in your project root:

```js title="eslint.config.mjs"
import baselineJs from 'eslint-plugin-baseline-js';

export default [
  { plugins: { 'baseline-js': baselineJs } },
  baselineJs.configs.recommended({ available: 'widely', level: 'warn' }),
];
```

The `recommended` preset applies to `.js`, `.cjs`, `.mjs`, and `.jsx` files.
It enables extra Web API and built-in checks with `preset: 'auto'`.
Without type information, these checks cover supported global and static uses. Instance member checks need type information.
JSX also needs parser settings; see [Examples](/docs/examples).

Add a file to check:

```js title="example.js"
const date = new Date();
const year = date.getYear();
```

Run ESLint:

```bash
pnpm exec eslint example.js
```

The rule reports:

```text
Feature 'getYear() and setYear()' (date-get-year-set-year) is not a widely available Baseline feature.
```

## Add TypeScript

Install the parser and TypeScript:

```bash
pnpm add -D @typescript-eslint/parser typescript
```

Use both presets if your project contains JavaScript and TypeScript.
The `recommended-ts` preset only matches `.ts` and `.tsx` files.

```js title="eslint.config.mjs"
import tsParser from '@typescript-eslint/parser';
import baselineJs from 'eslint-plugin-baseline-js';

export default [
  { plugins: { 'baseline-js': baselineJs } },
  baselineJs.configs.recommended({ available: 'widely', level: 'warn' }),
  {
    ...baselineJs.configs['recommended-ts']({ available: 'widely', level: 'warn' }),
    languageOptions: {
      parser: tsParser,
      parserOptions: {
        project: './tsconfig.json',
        tsconfigRootDir: import.meta.dirname,
      },
    },
  },
];
```

Your `tsconfig.json` must include the files you lint and the library declarations for the APIs you use.
Type information lets the rule identify supported instance members, such as `Set.prototype.difference`.
If parser services are missing, the rule skips checks that need types. The preset does not configure a parser or throw an error itself.

## Use mapped rules without extra API checks

Use `baseline` when you only want the mapped rules. These cover syntax and some built-ins.
Unlike the recommended presets, this helper returns an array, so spread it into your config:

```js title="eslint.config.mjs"
import baselineJs from 'eslint-plugin-baseline-js';

export default [
  { plugins: { 'baseline-js': baselineJs } },
  ...baselineJs.configs.baseline({ available: 'widely', level: 'warn' }),
];
```

This helper does not enable the extra Web API or built-in detectors.
It also does not configure TypeScript or JSX parsing.
