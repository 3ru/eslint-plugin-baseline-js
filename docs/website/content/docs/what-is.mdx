## Overview

`eslint-plugin-baseline-js` reports supported JavaScript features that exceed your
Baseline policy. It uses one rule: `baseline-js/use-baseline`.

- Set `available` to `'widely'`, `'newly'`, or a year.
- Use a recommended preset to enable Web API and JS builtin detection.
- Add TypeScript type information for supported instance-member checks.

The plugin checks JavaScript. Separate plugins can apply the same threshold to
[CSS and HTML](/docs/best-practices).

## Baseline data

The plugin bundles generated data from
[web-features](https://github.com/web-platform-dx/web-features).
Each release uses a fixed data snapshot. Linting does not fetch live browser data
or change feature status as time passes.

Detection also needs a matching rule or descriptor. A feature can exist in
web-features without a detector in this plugin. See the
[coverage report](/docs/meta/coverage) for mapped features and detection limits.

## TypeScript detection

With `@typescript-eslint/parser` and type information, supported checks inspect
the receiver's declared or inferred type. This helps distinguish platform methods
from methods with the same name.

Examples include:

- Array methods such as `toReversed()` and `toSorted()` (`array-by-copy`).
- `Intl.Locale` methods such as `getCalendars()` (`intl-locale-info`).
- Iterator helpers such as `map()` (`iterator-methods`) and `join()` (`iterator-join`).
- `Uint8Array` methods such as `toHex()` (`uint8array-base64-hex`).

These checks depend on the types and members available in your TypeScript
project. Some unions, aliases, and inherited types work. This does not guarantee
that every type or access pattern is detected.

The `type-aware` preset skips checks that need types when type information is
missing. See [Quick Start](/docs) for parser setup.

## Limits

The plugin checks source code against bundled browser data. It does not validate
your polyfills, build output, Node.js support, or runtime behavior. A clean lint
result does not guarantee browser compatibility.
