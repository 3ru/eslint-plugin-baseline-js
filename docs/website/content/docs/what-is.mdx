## Overview

`eslint-plugin-baseline-js` brings Baseline browser support data into your editor and lint checks.
It reports detected features that exceed your chosen policy.

- **One threshold:** choose `'widely'`, `'newly'`, or a year.
- **One rule:** `baseline-js/use-baseline` gives reports a consistent format.
- **Three surfaces:** check JavaScript syntax, JS builtins, and Web APIs.
- **One project policy:** use the same threshold with [CSS and HTML plugins](/docs/best-practices).

<Callout title="Start with your project" type="info">
Use `recommended` for JavaScript or `recommended-ts` with a configured TypeScript parser.
[Quick Start](/docs) walks through both setups.
</Callout>

## Detection that uses TypeScript types

Type information helps the plugin distinguish a platform method from a custom method with the same name.
For example, use the TypeScript preset with `available: 'widely'`:

```ts twoslash title="example.ts"
// @lib: esnext,dom
// ---cut---
const values = new Set([1, 2]);
//    ^?
values.difference(new Set([2])); // [!code error]

const custom = { difference: () => [] };
//    ^?
custom.difference(); // A custom method, so no set-methods report.
```

Hover over `values` and `custom` to compare their types. The platform call reports:

```text noCopy
Feature 'Set methods' (set-methods) is not a widely available Baseline feature.
```

Other supported checks include:

| Feature | Example |
| --- | --- |
| Array by copy (`array-by-copy`) | `values.toReversed()` and `values.toSorted()` |
| Intl.Locale info (`intl-locale-info`) | `locale.getCalendars()` |
| Iterator helpers (`iterator-methods`) | `iterator.map(fn)` |
| Iterator join (`iterator-join`) | `iterator.join(", ")` |
| Uint8Array base64/hex (`uint8array-base64-hex`) | `bytes.toHex()` |

The parser supplies the receiver's declared or inferred type.
Supported checks can also follow some aliases, unions, and inherited types.

<details>
<summary>What type information needs to include</summary>

Your TypeScript project must include the files and library declarations for the APIs you use.
The receiver's type must contain the member. Missing declarations or `any` types can hide a report.

These checks do not cover every type or access pattern.
When parser type information is missing, the plugin skips checks that need it and keeps other checks active.
See [Quick Start](/docs#add-typescript) for parser setup.

</details>

## Data from web-features

[web-features](https://github.com/web-platform-dx/web-features), maintained by WebDX, supplies the Baseline statuses behind the reports.
Each plugin release bundles a generated data snapshot.

<Callout title="Check the data and the detector" type="info">
A feature needs both Baseline data and a matching rule or descriptor.
Use [Coverage](/docs/meta/coverage) to see what is mapped before investigating a missing report.
</Callout>

<details>
<summary>Why results can differ from current browser support</summary>

Linting uses the installed snapshot. It does not fetch live browser data or advance feature status as time passes.
A newer plugin release may include updated data and detectors.

The plugin checks source code. It does not validate polyfills, build output, Node.js support, or runtime behavior.
Use it alongside tests in your target browsers.

</details>
