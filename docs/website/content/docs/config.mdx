## Presets (Flat Config)

Register the plugin under `baseline-js` before using a preset.
All helpers accept `available` and `level`. Their defaults are `'widely'` and `'error'`.
They also accept `baseline` as an alias for `available`.

| Helper | Return value | File scope | Additional detection |
| --- | --- | --- | --- |
| `configs.baseline()` | Config array | `js`, `cjs`, `mjs`, `jsx`, `ts`, `tsx` | Off |
| `configs.recommended()` | Config object | `js`, `cjs`, `mjs`, `jsx` | `auto` for Web APIs and built-ins |
| `configs['recommended-ts']()` | Config object | `ts`, `tsx` | `type-aware` for Web APIs and built-ins |

<Callout type="info" title="Choose a starting point">
Use `recommended` for JavaScript. Choose `recommended-ts` for TypeScript with type information.
Use `baseline` when you only want the mapped rules.
</Callout>

<Tabs groupId="preset" persist items={["recommended", "recommended-ts", "baseline"]}>
<Tab value="recommended">

This preset enables additional detection for JavaScript files. It does not apply to TypeScript files.

```js title="eslint.config.mjs"
import baselineJs from 'eslint-plugin-baseline-js';

export default [
  { plugins: { 'baseline-js': baselineJs } },
  baselineJs.configs.recommended({ available: 'widely', level: 'warn' }), // [!code ++]
];
```

</Tab>
<Tab value="recommended-ts">

Install `typescript` and `@typescript-eslint/parser`. Include the files you lint in your `tsconfig.json`.

```js title="eslint.config.mjs"
import tsParser from '@typescript-eslint/parser'; // [!code ++]
import baselineJs from 'eslint-plugin-baseline-js';

export default [
  { plugins: { 'baseline-js': baselineJs } },
  {
    ...baselineJs.configs['recommended-ts']({ available: 'widely' }),
    languageOptions: {
      parser: tsParser, // [!code ++]
      parserOptions: {
        project: './tsconfig.json', // [!code ++]
        tsconfigRootDir: import.meta.dirname,
      },
    },
  },
];
```

The receiver's type must resolve to a supported built-in or Web API type. A value typed as `any` can hide an instance-member check.

</Tab>
<Tab value="baseline">

Spread the array returned by `configs.baseline()` into your config array.

```js title="eslint.config.mjs"
import baselineJs from 'eslint-plugin-baseline-js';

export default [
  { plugins: { 'baseline-js': baselineJs } },
  ...baselineJs.configs.baseline({ available: 'widely' }), // [!code focus]
];
```

</Tab>
</Tabs>

<Callout type="warn" title="A preset does not configure your parser">
TypeScript needs a TypeScript parser and a project. JSX also needs parser support.
See [Examples](/docs/examples) for complete project setups.
</Callout>

## Rule options

Use these options with `baseline-js/use-baseline`.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `available` | `'widely'`, `'newly'`, or a year | `'widely'` | Set the Baseline threshold. |
| `baseline` | Same as `available` | — | Compatibility alias. `available` takes precedence. |
| `includeWebApis` | Boolean or an options object | `false` | Enable additional Web API detection. |
| `includeJsBuiltins` | Boolean or an options object | `false` | Enable additional JavaScript built-in detection. |
| `ignoreFeatures` | `string[]` | `[]` | Skip feature IDs across all detectors. Supports `/regex/` strings. |
| `ignoreNodeTypes` | `string[]` | `[]` | Skip reports on matching ESTree node types. Supports `/regex/` strings. |

`available: 'widely'` reports features that are not widely available.
`available: 'newly'` reports features with Limited availability.
A year reports features that entered Baseline after that year, plus features with Limited availability.

These checks use the data bundled with the installed plugin. See [Concepts](/docs/concepts) for the policy and coverage limits.

## Feature detection

The rule always checks its mapped features. Additional Web API and built-in detection is off unless you enable it.

If you already use the rule directly, add these two options for the recommended detection behavior:

```js title="eslint.config.mjs"
import baselineJs from 'eslint-plugin-baseline-js';

export default [
  {
    files: ['**/*.{js,mjs,cjs}'],
    plugins: { 'baseline-js': baselineJs },
    rules: {
      'baseline-js/use-baseline': ['error', {
        available: 'widely',
        includeWebApis: { preset: 'auto' }, // [!code ++]
        includeJsBuiltins: { preset: 'auto' }, // [!code ++]
      }],
    },
  },
];
```

Both `includeWebApis` and `includeJsBuiltins` accept the same options:

```ts title="Common detection options"
type Include = boolean | {
  preset?: 'safe' | 'auto' | 'type-aware';
};
```

| Value | Behavior |
| --- | --- |
| `false` or omitted | Disable this additional detector. |
| `true`, `{}`, or `{ preset: 'safe' }` | Enable patterns that do not need type information. |
| `{ preset: 'auto' }` | Also use type information when the parser provides it. |
| `{ preset: 'type-aware' }` | Enable checks that need types when the parser provides them. |

Without type information, `auto` and `type-aware` skip instance-member and other type-dependent checks. They still run the remaining checks and do not throw an error.

The safe checks include global constructors, static members, and selected literal argument patterns. They do not cover every API or usage pattern.

<details>
<summary>Advanced options: type overrides and accepted compatibility settings</summary>

```ts title="Complete detection options"
type Include = boolean | {
  preset?: 'safe' | 'auto' | 'type-aware' | 'heuristic';
  useTypes?: 'off' | 'auto' | 'require';
  heuristics?: 'off' | 'conservative' | 'aggressive';
  only?: string[];
  ignore?: string[];
};
```

`useTypes` overrides the preset's type setting. `safe` defaults to `off`, `auto` to `auto`, and `type-aware` to `require`.

Type information requires a parser service with a TypeScript program. Selecting a preset alone does not create one.

Type use is shared across the two detectors. Enabling types for either detector can enable typed checks for both included feature sets.

The schema also accepts `preset: 'heuristic'` and `heuristics`. These options do not add heuristic detection in the current implementation.
Use `safe`, `auto`, or `type-aware` for the behavior described above.

</details>

### Feature filters

`only` and `ignore` accept exact web-features IDs within that detector. They do not support regular expressions or change the mapped-rule checks.
An empty `only` array does not limit detection. Add this `rules` property to your existing config object.

```js title="Filter additional built-in checks"
rules: {
  'baseline-js/use-baseline': ['error', {
    available: 'widely',
    includeJsBuiltins: {
      preset: 'auto',
      only: ['iterator-join', 'set-methods'], // [!code focus]
    },
  }],
}
```

<Callout type="info" title="Choose the right filter">
Use `only` to narrow one additional detector. The instance methods in this example also need type information.
Use `ignoreFeatures` to suppress a feature across all detectors.
</Callout>

```js title="Ignore features or report node types"
rules: {
  'baseline-js/use-baseline': ['error', {
    available: 2018,
    ignoreFeatures: ['nullish-coalescing', '/^optional-/'], // [!code ++]
    ignoreNodeTypes: ['WithStatement', '/Expression$/'], // [!code ++]
  }],
}
```

## Legacy config (.eslintrc)

Use Flat Config with this package. Its ESM default export does not load correctly through ESLint 9's legacy plugin loader.

<Callout type="warn" title="Seeing a missing-rule error?">
`Definition for rule 'baseline-js/use-baseline' was not found` can result from the legacy plugin loader.
Move the setup to `eslint.config.mjs` using a preset above.
</Callout>

[ESLint 10 also removes legacy config support](https://eslint.org/docs/latest/use/migrate-to-10.0.0#old-config-format-no-longer-supported).
See [Examples](/docs/examples) for supported Flat Config setups.

## Use with oxlint

Load the package as an [oxlint JavaScript plugin](https://oxc.rs/docs/guide/usage/linter/js-plugins).

```jsonc title=".oxlintrc.json"
{
  "jsPlugins": ["eslint-plugin-baseline-js"], // [!code ++]
  "rules": {
    "baseline-js/use-baseline": [
      "warn",
      {
        "available": "widely",
        "includeWebApis": { "preset": "auto" },
        "includeJsBuiltins": { "preset": "auto" }
      }
    ]
  }
}
```

<Callout type="warn" title="Type information is required for some checks">
The plugin's instance-member checks need TypeScript parser services. The oxlint integration does not provide them.
This skips checks such as `Set.prototype.difference()` and `Iterator.prototype.join()`. Use ESLint with a configured TypeScript parser for these checks.
</Callout>

See [oxlint](/docs/oxlint) for setup details and the [FAQ](/docs/meta/faq) for detection limits.

## Messages

Messages identify the detected API, relevant options, or feature.
The web-features ID appears in parentheses. Use it with `ignoreFeatures` to skip the whole feature, which can include several APIs.

<Tabs items={["widely", "newly", "Year"]}>
<Tab value="widely">

With `available: 'widely'`, a feature must be widely available.

```js title="example.js"
const year = new Date().getYear(); // [!code error]
```

```text title="ESLint report" noCopy
'getYear' on Date is not Baseline Widely available (date-get-year-set-year).
```

</Tab>
<Tab value="newly">

With `available: 'newly'`, newly and widely available features are allowed. Limited features are still reported.

```js title="example.js"
const year = new Date().getYear(); // [!code error]
```

```text title="ESLint report" noCopy
'getYear' on Date is not Baseline Newly available (date-get-year-set-year).
```

</Tab>
<Tab value="Year">

With `available: 2019`, a feature that entered Baseline in 2020 exceeds the target.

```js title="example.js"
const total = 1n; // [!code error]
```

```text title="ESLint report" noCopy
'BigInt' became Baseline in 2020 and exceeds 2019 (bigint).
```

A feature with Limited availability also exceeds a year target:

```js title="example.js"
const year = new Date().getYear(); // [!code error]
```

```text title="ESLint report" noCopy
'getYear' on Date has Limited availability and exceeds 2019 (date-get-year-set-year).
```

</Tab>
</Tabs>

<details>
<summary>Why does a message contain a date such as ≤2018?</summary>

An upper-bound date keeps its `≤` prefix in the message. The policy compares the numeric year.
A date of `≤2018` exceeds a 2017 target and meets a 2018 target.

</details>

## Standalone rules

Most projects should use `baseline-js/use-baseline`. It enables mapped checks based on the selected Baseline threshold.

These rules are also exported directly. When enabled directly, they report matching usage without checking a Baseline threshold.

| Rule | Checks |
| --- | --- |
| `baseline-js/no-atomics-pause` | `Atomics.pause` calls and member access. |
| `baseline-js/no-bigint64array` | `BigInt64Array` and `BigUint64Array` construction, calls, and member access. |
| `baseline-js/no-function-caller-arguments` | Non-computed `.caller` and `.arguments` access. |
| `baseline-js/no-math-sum-precise` | `Math.sumPrecise` calls and member access. |
| `baseline-js/no-temporal` | Direct `Temporal` member access and construction. |

The global-based rules check for shadowed globals and support `window` and `globalThis` prefixes. They do not follow aliases.
`no-function-caller-arguments` does not check receiver types, so it can report those properties on ordinary objects.
