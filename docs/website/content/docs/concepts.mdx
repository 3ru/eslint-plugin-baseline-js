<Callout title="Three surfaces of JavaScript" type="info">
JavaScript checks cover language syntax, builtins, and Web APIs.
Use the examples below to find the settings your code needs.
</Callout>

## JS syntax

- **Examples:** nullish coalescing (`a ?? b`), optional catch binding, top-level `await`, and template literals.
- **What it is:** ECMAScript operators and statements.
- **How we detect it:** mapped rules from `eslint-plugin-es-x`, ESLint core, and this plugin.
- **Setup:** mapped checks run in every preset.

<Callout title="The minimal preset also checks some builtins" type="info">
`configs.baseline()` enables mapped rules, including checks for `Temporal` and `Math.sumPrecise`.
It leaves the separate Web API and JS builtin descriptor checks disabled.
</Callout>

## JS builtins

- **Examples:** `Intl.Segmenter`, `Set.prototype.difference()`, and `Iterator.prototype.join()`.
- **What it is:** the ECMAScript standard library: globals, classes, and methods.
- **How we detect it:** descriptors generated from web-features, plus the mapped checks above.
- **Setup:** both recommended presets enable `includeJsBuiltins`.

Supported constructors, static methods, and globals can work without types.
Instance-member descriptors use TypeScript type information to identify the receiver.

## Web APIs

- **Examples:** `fetch`, `AbortSignal.any()`, `IntersectionObserver`, and `Element.animate()`.
- **What it is:** browser APIs for features such as the DOM, networking, media, and sensors.
- **How we detect it:** descriptors generated from web-features.
- **Setup:** both recommended presets enable `includeWebApis`.

Use the TypeScript setup for supported instance-member checks, such as methods called on an element or response.
See [Quick Start](/docs#add-typescript) to connect the parser.

## Pick a preset

| Your setup | Start with |
| --- | --- |
| JavaScript | `configs.recommended()` |
| TypeScript with type information | `configs['recommended-ts']()` |
| JavaScript and TypeScript | Both recommended presets |
| Mapped rules without extra descriptor checks | `configs.baseline()` |

<details>
<summary>How coverage and runtime targets affect a check</summary>

A mapped feature has a rule or descriptor. It can still have unsupported access patterns, such as dynamic property access or aliases.
The [coverage report](/docs/meta/coverage) lists the available checks.

The plugin uses browser Baseline status from its bundled data. It does not select Node.js versions, worker environments, or custom browser targets.
ESLint's `languageOptions.globals` controls known global names; it does not change the Baseline policy.

The plugin does not account for polyfills or transpiler output. Test your app in its target environments.

</details>
