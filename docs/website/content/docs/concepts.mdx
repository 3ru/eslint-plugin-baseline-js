## JS syntax

Syntax includes operators and statements, such as nullish coalescing (`a ?? b`)
and top-level `await`.

The plugin maps supported features to `eslint-plugin-es-x`, ESLint core, or local
rules. These mapped checks run in every preset. The mapping also includes some
builtins, such as `Temporal` and `Math.sumPrecise`.

The `baseline` preset enables these mapped checks. It leaves the separate Web
API and JS builtin descriptor checks disabled.

## JS builtins

Builtins are the ECMAScript standard library. Examples include `Intl.Segmenter`,
`Set.prototype.difference()`, and `Iterator.prototype.join()`.

Set `includeJsBuiltins` to enable descriptor checks generated from web-features.
Both recommended presets enable them.

Supported constructor calls, static methods, and globals can work without types.
Instance-member descriptors need TypeScript type information. Some builtins also
have mapped checks that run without this option.

## Web APIs

Web APIs include browser features such as `fetch`, `AbortSignal.any()`, and
`IntersectionObserver`.

Set `includeWebApis` to enable their descriptor checks. Both recommended presets
enable them. Supported instance members need TypeScript type information.

Descriptors match specific code patterns. They do not cover every way to access
an API, including arbitrary dynamic property access or aliases.

## Baseline and runtime support

The plugin uses the browser Baseline status stored in its bundled data. It does
not select Node.js versions, worker environments, or custom browser targets.

ESLint's `languageOptions.globals` controls which global names ESLint knows. It
does not change this plugin's Baseline policy or filter its feature data.

The plugin does not account for polyfills or transpiler output. Test your app in
its target environments.

## Coverage

The [coverage report](/docs/meta/coverage) lists mapped features and descriptor
checks. A mapped feature can still have unsupported access patterns.
